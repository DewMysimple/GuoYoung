# 系统架构

## 模块职责与边界

主页面由 `src/App.tsx` 编排收藏、GitHub、历史、设置和拖拽；界面组件在 `src/components/`，状态编排在 `src/hooks/`，业务与平台适配在 `src/lib/`。`use-site-hub.ts` 是持久收藏入口，`site-state.ts` 做业务变换，`state-store.ts` 适配读写，`storage.ts` 负责兼容解析与迁移；不增加第二个全局状态源。

第一阶段URL规则归collection/model/site-url；第二阶段将两项分组重排归groups/model/group-reorder，site-utils保留同名兼容出口、useSiteHub直连；GitHub来源去重、报告排序与成功路径摘要归github/model/repository-refresh，App保留串行请求、时钟/状态和一次批量提交。新模型仅依赖src/types.ts纯类型。业务归属矩阵、过渡规则和下一阶段前置接口的唯一入口是 [[知识/业务模块边界与架构基线|业务模块边界与架构基线]]。architecture:check与合成测试继续接入CI，不增加全局许可。

扩展 popup 共用业务和存储，`src/background.ts` 只桥接历史变更事件；浏览历史直接读浏览器 API。完整模块定位见 [[知识/系统架构详解|系统架构详解]]，拖拽修改先读 [[知识/拖拽交互契约|拖拽交互契约]]。

## 数据流与依赖

界面命令 → useSiteHub → 纯业务变换 → 存储适配 → 订阅回馈。网页用 localStorage，扩展用 chrome.storage.local；固定 `site-hub:v1`，默认与迁移目标 state **v28**（`src/data/defaults.ts`、`src/lib/storage.ts`）。选择、拖拽会话和未保存设置草稿为临时状态。壁纸/字体 Blob 在 IndexedDB `site-hub-assets` v2 的独立 stores，state 保留引用（`asset-store.ts`）。

React/TypeScript/Vite/Tailwind 构成应用；dnd-kit 控制排序，Motion 固定版本。GitHub 公开 API 和浏览器 API 是外部依赖；history 为可选权限，见 `public/manifest.json`、`src/lib/github-repository-api.ts`。

## 运行与部署

`npm.cmd ci` 安装锁定依赖，`npm.cmd run dev` 默认 5173。`build` 生成 `dist/`；`build:extension` 生成 `dist-extension/`，由 Vite mode 分流，未维护两套产品源码。Node 支持范围由 `package.json` 的 engines 决定；Windows 使用 npm.cmd。扩展交付遵循 [[知识/扩展与构建交付|扩展与构建交付]]，运行时代码提取触发版本递增及打包。
