# 系统架构

[[Wiki/MOC_项目知识|← 返回项目知识 MOC]]

## 技术栈与入口

- React 19 + TypeScript + Vite 7 + Tailwind CSS 4；Tailwind 通过 Vite 插件加载。
- dnd-kit 负责排序位移，framer-motion 精确锁定 `12.23.12`，`motion-dom` 同版本 override。
- Phosphor 与 Simple Icons 提供图标；Vitest + Testing Library 验证业务与组件，Playwright 验证桌面 Chrome 和 Pixel 7 模拟设备。
- `index.html` → `src/main.tsx` → `src/App.tsx` 为主应用；扩展另有 `popup.html` → `src/popup/main.tsx` 与 `src/background.ts` 两个入口。
- `vite.config.ts` 由构建 mode 决定网页 / 扩展入口、资源路径与输出目录；不维护两份应用源码。

## 模块边界

| 位置 | 职责 |
| --- | --- |
| `src/App.tsx` | 收藏与 GitHub 工作区、搜索、选择、弹窗、拖拽和设置草稿的界面编排 |
| `src/hooks/use-site-hub.ts` | 持久化收藏状态的 React 入口，编排加载、订阅、保存和业务操作 |
| `src/hooks/use-theme.ts`、`use-wallpaper.ts` | 主题应用、壁纸资源与页面样式生命周期 |
| `src/lib/site-state.ts` | 添加、编辑、分组、回收站和仓库导入等状态变换 |
| `src/lib/state-store.ts` | 网页 localStorage / 扩展 chrome.storage.local 适配与扩展变更订阅 |
| `src/lib/storage.ts` | `site-hub:v1` 数据解析、默认值补全及逐级迁移至 state v14 |
| `src/lib/data-transfer.ts` | 整库与分组资源包的序列化、校验与导出边界 |
| `src/lib/github-workspace.ts`、`github-repository-api.ts` | GitHub URL 路由、工作区兼容与公开仓库分页读取 |
| `src/lib/browser-runtime.ts`、`browser-history.ts`、`bookmark-manager.ts` | 浏览器 API 能力检测、权限与平台适配 |
| `src/components/` | 收藏卡片、分组、设置、GitHub 导入 / 刷新详情及独立历史视图 |
| `src/popup/` | 当前页收藏与浏览器书签管理，复用存储与业务模块 |
| `src/background.ts` | MV3 service worker 历史变更事件通知桥 |
| `src/data/`、`src/types.ts` | 默认数据、图标选项与共享类型 |
| `src/styles.css` | 设计令牌、全局样式、组件样式与响应式规则 |

模块行数与维护优先级只在带日期的 [[Wiki/工程维护清单|工程维护清单]] 中记录，避免作为长期接口事实反复复制。

## 状态与数据流

界面操作经 `useSiteHub` 调用业务函数得到下一份收藏 state，再交给存储适配器保存；扩展 popup 使用同一存储契约，存储变更订阅将其他扩展页面的修改反馈到主应用。

持久化收藏 state 与页面临时状态分开：拖拽预览、弹窗、搜索上下文和未保存设置草稿由界面维护，确认后才提交。历史视图直接读取浏览器历史 API，不写入收藏 state；本地壁纸二进制保存在 IndexedDB。

## 保持的约束

- 保留自研 hook 与业务函数的边界，不引入 Redux / Zustand 作为第二份状态源（[[Wiki/决策/ADR-001|ADR-001]]）。
- state 新增字段必须迁移且只补不覆盖；存储键不随产品文案或仓库名称变化（[[Wiki/数据与存储契约|数据与存储契约]]）。
- 排序位移只由 dnd-kit 控制，不叠加 Motion transform；拖拽修改先读 [[Wiki/拖拽交互契约|拖拽交互契约]]。
- `npm run dev` / `runStart.cmd` 默认使用 5173；E2E 与截图使用 4173。
- `dist/`、`dist-extension/`、测试报告和本地验收产物是生成物；源码中仅保留 `docs/images/` 的少量公开展示图片。

## 维护方向

本轮评估认为现有分层可继续使用。App、全局 CSS、设置面板和 E2E 单文件较大，后续随对应功能需求渐进提取；优先提取 GitHub 导入编排、设置草稿等边界清楚的模块，拖拽核心待可复现回归覆盖完整后再动。详见 [[Wiki/工程维护清单|工程维护清单]]。
