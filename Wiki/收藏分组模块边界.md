# 收藏分组模块边界

[[Wiki/MOC_项目知识|← 返回项目知识 MOC]]

## 维护问题与边界

“全部－按分组显示”同时支持网站排序、跨组迁移、分组排序与两类选择。此前状态 reducer 已独立，但 DOM 测量、原生事件、rAF、菜单和渲染仍在 App 中交叉调用；首次渲染注册的监听器会捕获旧分组和选择状态。把函数移出文件并不能自动解决这个生命周期问题。

1.1.81 将职责分为下表；持久化入口仍是 useSiteHub，选择仍是 useCollectionSelection，不引入第二份全局状态。App 只保存传给页面的拖拽展示快照；网站 hook 内的冻结提交基准不接受界面反向修改。

| 需求或职责 | 唯一修改入口 | 不应放入的逻辑 |
| --- | --- | --- |
| 分组标题、数量、右侧多选 | `components/group-section-header.tsx` | 不读存储，不拥有 sortable 位移 |
| 相邻分组插入、菜单焦点 | `components/group-insert-control.tsx` | 不计算网站落点或写分组顺序 |
| 加号与三点按钮尺寸 | `components/compact-icon-button.tsx`、`grouped-collection.css` | 不增加分组容器整体缩进 |
| 分组列表组成 | `components/grouped-collection.tsx` | 不创建独立选择集合 |
| 平铺、单组和分组网站网格 | `components/collection-site-grid.tsx` | 不复制 SiteCard 配置或另一套网格几何 |
| 分组 sortable 外壳 | `components/sortable-group-section.tsx` | 只绑定 dnd-kit transform 和指针监听；标题无键盘排序 |
| 分组排序编排 | `hooks/use-group-sorting.ts` | 会话事实仍由 useGroupSortSession 持有，落点算法仍由 group-sort 提供 |
| 网站拖拽事务 | `hooks/use-site-dragging.ts` | 不重写持久化规则；只通过注入的 commitSites 提交 |
| DOM 几何、交叠面积 | `lib/collection-drag-geometry.ts` | 不持有 React 状态，不提交排序 |
| dnd 标识与激活距离 | `lib/collection-drag-ids.ts`、`collection-drag-sensors.ts` | lib 与 hooks 不反向依赖分组 UI 组件 |
| 原生移动/取消、标签边缘滚动 | `hooks/use-drag-window-events.ts`、`use-tab-edge-scroll.ts` | 两种拖拽共用，不能各自复制一套窗口事件 |
| 稳定监听器读取最新状态 | `hooks/use-latest-event.ts` | 不把业务数据强行冻结到空依赖 effect 中 |
| 网站手势后误点击与 href 恢复 | `hooks/use-site-click-guard.ts` | 不参与排序或选择提交 |

## 布局约束

- 分组列表不再为外置按钮整体右移；页面标题、分组图标与首张卡片共用左边缘。平铺和分组网格共用列宽及 gap，组内不叠加 2px padding。
- 分组加号位于紧凑标题的操作区，与三点按钮共用 28px 命中区、8px 圆角和无阴影样式。图标、标题、数量、加号和右侧多选垂直居中；多选与上方显示按钮右边缘对齐。
- 加号在桌面仍由紧凑标题、自身区域和键盘焦点揭示；触屏常驻。整行空白与右侧多选不揭示加号。选择模式在同一控件槽位显示圆形勾选，避免切换时挤动标题。
- 长名称省略、保留 title；数量和操作不压缩。菜单锚定标题左缘，受视口宽度约束；键盘方向键选择、Esc 返回触发器，点击另一组只保留一个菜单。
- 保留原页面外形与壁纸轻微透底，不添加整条白色底板。壁纸下仅给紧凑动作按钮加局部透底，并提高数量文字对比度。网站 favicon 解析流程不属于本次标题图标治理范围。

## 生命周期约束

- 原生事件和 rAF 使用最新已提交的回调；保持 50px 网站激活、8px 分组激活、18px 滞回、450ms 标签预览切组，以及单一意图提交规则。
- blur、pagehide、页面隐藏、鼠标/笔 pointercancel 清空活动或待激活会话，先清意图再释放传感器。释放事件有重入保护，防止待激活 React 状态尚未提交时递归取消。
- 顶部标签与纵向标题在 8px 激活前也登记 pending；窗口离开时同时取消分组传感器和标签长按计时，返回后移动鼠标不得突然启动拖拽或打开管理器。
- TouchSensor 以 touchcancel 结束；浏览器取消触摸兼容 pointer 流不等于 touch 流已结束，不能直接取消仍在进行的触屏拖拽。
- 拖拽期间真实网站/分组快照更新会取消旧事务，防止用冻结数据覆盖外部保存。分组切换后的双 rAF 几何重捕获核对原会话快照，不能回写下一次拖拽。
- 分组无目标/取消保持选择，有效提交才清理；网站单次提交仍读取冻结快照与当前 SiteDropIntent。全局持久化事务并发问题仍见数据契约，取消旧拖拽不是跨进程原子锁。

## 验证与后续修改

- `grouped-layout.spec.ts` 覆盖三种布局、大字号、长名称、左右/垂直几何、菜单键盘与待激活取消；`group-sort.spec.ts`、`site-drag.spec.ts` 保留排序、跨组、批量、取消和真实触屏回归。
- 原生事件 hook 验证 rerender 后读取最新工作区/选择、先清理后释放、重入保护与 touchcancel 区分；网站 hook 验证外部保存取消冻结事务。
- 修改样式需检查普通、网站选择、分组选择、拖动来源和浮层五种状态，以及窄屏和壁纸。拖动截图只取视口，不用 fullPage 改变手势布局。
- 本次减少的是跨职责修改与状态闭包风险，不宣称工程不再出现 Bug。网站 hook 仍有复杂落点分支；后续应以具体失败证据提取纯意图变换，不以文件行数为目的重写。
