# 收藏搜索匹配

[[Wiki/MOC_项目知识|← 返回项目知识 MOC]]

## 数据与模块边界

- 收藏主页、GitHub 与具体分组共用 `filterSites`，搜索非空时沿用跨工作区收藏范围；清空后恢复来源分组。浏览器历史仍按独立 API 搜索，不混入收藏。
- `lib/collection-search.ts` 负责文本归一化、匹配及相关度；`site-utils.filterSites` 负责可见分组边界、稳定排序与返回网站；App 在搜索时直接使用相关度顺序，不用已保存的排列方式覆盖它。清空搜索恢复原排列，搜索不会写入网站顺序。
- `WorkspaceSearch` 统一组合输入生命周期，`compositionstart/end`、原生 `isComposing` 和兼容 `keyCode=229` 保护候选选择；组合期间的 input 仍实时筛选。Enter 选字不执行网页搜索，选字完成后正常 Enter 才调用原有搜索入口。
- 拼音采用固定版本 `pinyin-pro`，随网页/扩展本地打包；不查询远端建议，不持久化派生索引、不增加 state 字段。词组读音和 API 依据 [pinyin-pro 官方文档](https://pinyin-pro.cn/en/use/pinyin.html)。文本索引按原文字串缓存，最多 2,000 项，改名后生成新索引，不会复用旧名称的读音。

## 匹配与排序

| 输入 | 可匹配的名称或范围 |
| --- | --- |
| `k'i'mi`、`ki’mi`、全角 `ＫＩＭＩ` | Kimi |
| `blbl`、`bilibili`、`bi'li'bi'li` | 哔哩哔哩 |
| `wjbk` | 维基百科 |
| `cqyh` | 重庆银行（词组读音） |
| `wangysj` | 网页设计（音节前缀混用） |
| `uidxk`、`so`、`km` | UI动效库、Stack Overflow、Kimi |
| `sj figma` | 设计分组中的 Figma（多个词均需命中） |

- 名称原文精确/前缀/包含优先，然后是全拼、首字母、混合音节前缀；英文省略元音的缩写只作低置信度补充。网址与分组名称有降权，避免分组命中盖过想找的网站本身。
- 归一化兼容大小写、全角、音调与输入法分隔符。普通直接文本搜索保持，单个拉丁字母不猜中文首字母，降低短输入噪声。
- 多音字按词组词典处理，不枚举任意读音；不承诺对所有输入法、双拼编码或任意错拼都能猜中。输入法若不向网页发出预编辑内容，网页只能在收到输入后筛选。
- 输入非空时收起“最近搜索”，让匹配结果直接可见；空输入时仍可选历史记录。组合期间不截获候选的上下键，取消搜索恢复原工作区上下文。

## 验证入口

- `collection-search.test.ts`：输入法分隔符、拼音/缩写、词组音、混合字段、相关度、改名和分组边界。
- `workspace-search.test.tsx`：组合期间实时文本更新、候选键、Enter 与旧浏览器兼容按键码。
- `group-search-improvements.spec.ts`：真实 Chrome 的 `Input.imeSetComposition` 预编辑、候选 Enter、输入后结果和相关度顺序，桌面与移动 project 均执行。
