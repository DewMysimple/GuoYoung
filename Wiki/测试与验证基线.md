# 测试与验证基线

[[Wiki/MOC_项目知识|← 返回项目知识 MOC]]

> 本页记录测试分层与口径。数字以 2026-09-07 的完整流水线实跑为准。

## 测试分层与入口

- **单元**：`npm test`（vitest），**19 个测试文件、181 例**，覆盖 `src/lib/` 与组件逻辑。
- **E2E**：`npm run test:e2e`（Playwright），入口 `e2e/site-hub.spec.ts`，**72 条 test**。
- **类型**：`npm run build` 内含 `tsc -b` 类型检查，是每轮流水线第一关。

## E2E 计数口径

- Playwright `projects` 含 **chromium + mobile(Pixel 7)** 两个；72 条 test 在两 project 上各跑一次，理论 **144 次执行**；本轮以单 worker 完整实跑为 **106 passed / 36 skipped / 2 failed**。GitHub 官方入口整卡点击、历史新标签页打开、工作区迁移/撤销、URL 分流、全局收藏搜索、作者仓库预览/确认、重复跳过、分页失败保护、固定弹窗外壳的外层/内部滚动断言及桌面/移动端截图回归均通过；既有失败项仍为 2 个桌面手动卡片 `is-drop-target` 时序回归，不涉及本轮功能路径。
- 移动端因 `fullyParallel: true` 存在并发超时历史线索（见 [[Wiki/当前状态|当前状态]] 遗留项 1）；本轮完整实跑未复现。

## 视觉巡检不可替代

- 布局/拖拽手感/图标清晰度等**必须真实浏览器截图人工巡检**，自动化无法完全覆盖；尤其拖拽抖动类问题需录屏逐帧核对（见 [[Wiki/日志/工程讨论/第002次|工程讨论·第002次]]）。

## 已知不稳定用例

- 移动端 E2E 并发超时（遗留项 1）；外部 GitHub 导航已改为本地路由响应，避免验收结果受网络速度影响。
- 拖拽落点类用例对渲染时序敏感；1.1.6 已增加偏心抓取、松手前目标框移动、双向、跨行与跨组回归。
