# 扩展与构建交付

[[Wiki/MOC_项目知识|← 返回项目知识 MOC]]

## 双模式构建

- 同一套源码，仅以构建模式区分产物（见 [[Wiki/决策/ADR-002|ADR-002]]）：
  - `npm run build` → 网页版 `dist/`。
  - `npm run build:extension`（`vite build --mode extension`）→ MV3 扩展版 `dist-extension/`，接管浏览器新标签页。
- 扩展专属 JS/HTML 入口由 `--mode extension` 启用；`public/manifest.json` 是静态资源，会复制到两种构建目录，网页目录不是完整扩展。

## manifest 与权限

- 扩展 manifest 为 MV3；常驻 permissions 为 `favicon` / `activeTab` / `bookmarks` / `search` / `storage`，浏览历史使用首次点击时申请的可选 `history` 权限，**不申请全站读取权限**。
- `history` 权限会让浏览器显示“读取和更改浏览历史”警告；权限被拒绝时只关闭历史能力，不影响收藏主页。
- 版本号以 `public/manifest.json` 为单一真源（当前 1.1.101）；网页构建与扩展构建都从该文件复制 manifest，交付前须核对产物版本。

## 浏览器历史记录

- 扩展新标签页顶栏品牌右侧依次提供“收藏主页”“GitHub”和“历史记录”入口；网页构建保留入口，但显示扩展版可用说明。
- `src/lib/browser-history.ts` 只适配 Chrome / Edge 的 `chrome.history` API，以浏览器当前配置文件历史为唯一数据源，不写入 `site-hub:v1`、收藏导出或本地历史副本。
- 权限和历史方法统一兼容 Promise 与 callback 调用；授权完成后重新检查权限，异常时在历史视图显示可重试错误。
- 授权调用必须直接从用户点击进入，在 request 前不插入 await，以保留浏览器用户手势。1.1.85 监听 permissions.onAdded/onRemoved；撤销立即清空缓存显示并使在途读取/删除结果失效，重新授权、焦点恢复、页面可见及重试时重新检查 contains。并发权限检查只接受最新结果，不用旧响应覆盖撤销事件。
- background 在撤销时注销历史监听并清除注册标记，再授权后重新挂载；页面直接订阅与后台通知并存，不依赖 service worker 一直存活。
- 原生验收：先构建扩展，再在 Windows 执行 `node scripts/verify-native-history.mjs`。脚本使用 Playwright 自带 Chromium、系统临时目录中的全新配置文件和 Windows UI Automation，实际点击浏览器“拒绝/允许”，不替换 API 或预植权限。验证 125 条合成历史、搜索、URL 删除、权限撤销/重授、双页面同步、刷新及浏览器重启；产物写入当前版本 artifacts。浏览器资料不能放进 Vite 监视的工程目录，Windows 会对 Cookies 等文件加锁。
- 1.1.85 原生验收浏览器为 Chromium 151.0.7922.34；callback 风格 Edge API 另由单元与 E2E 覆盖，未将其宣称为真实 Edge 安装或企业策略环境实测。扩展无法绕过用户拒绝或浏览器策略。平台约束以 [Chrome permissions](https://developer.chrome.com/docs/extensions/reference/api/permissions) 和 [Chrome history](https://developer.chrome.com/docs/extensions/reference/api/history) 为准。
- 历史视图按 URL 汇总后再按主域名聚合为复用收藏主页 `site-card` 几何与内容结构的长方形站点卡片；搜索框复用收藏主页的 `workspace-intro` / `search-panel` / `search-input` 结构。历史页搜索框置顶并与收藏主页保持同一高度，移除大标题区，数量统计并入筛选工具栏；时间范围默认“近 7 天”，选择器为左侧带历史记录图标的中等圆角按钮，整颗控件可点击并使用自绘圆角选项菜单，标签与选项文字使用更清晰的 12/13px 字号和抗锯齿设置，避免原生下拉层的方形系统样式；默认不显示选择控件，点击站点卡片进入独立历史详情子页面，不在卡片内嵌展开且不显示展开箭头；总览站点卡片和详情 URL 卡片支持整卡 50px 拖拽、原位淡化和 `DragOverlay` 浮层，不显示拖拽手柄，不提供收藏分组落点或排序提交，释放/取消只清理视觉状态并抑制误打开；点击历史页“多选”后才在卡片右下角显示与收藏主页 `SiteCard` 一致的圆形选择控件，支持整卡选择、站点全选和部分选中，Esc 退出选择；页面内返回按钮与浏览器原生后退都能退出详情并恢复列表位置，分组管理、添加/编辑和 GitHub 导入面板标题栏提供返回入口；设置仅保留关闭；保留全部、今天、昨天、近 7 天、近 30 天、标题/URL 搜索、单条删除和 URL 级勾选批量删除，不提供清空全部或范围清理入口，删除 URL 会删除该 URL 的全部访问记录。
- `src/background.ts` 是 MV3 service worker，仅监听 `onVisited` / `onVisitRemoved` 并通知打开的页面刷新；历史页获得焦点或重新可见时也会主动查询，补偿浏览器同步和 service worker 休眠带来的延迟。站点详情导航状态只保存在当前历史页面会话，不写入收藏 state。
- 首次历史查询保留加载保护，短于 250ms 的读取只呈现稳定的历史页布局；较慢读取才显示简洁文字提示，不再绘制 6 张瞬时占位卡。已有结果刷新时保留卡片与数量摘要；权限撤销仍立即清空。
- Chrome 与 Edge 的历史独立；无痕窗口历史不纳入本功能。原生 API 没有稳定的按单次 `visitId` 删除接口，因此本功能以 URL 或范围为删除粒度。

## GitHub 独立收藏工作区

- 顶栏顺序固定为“收藏主页 → GitHub → 历史记录”。GitHub 工作区与主收藏共用 `site-hub:v1` 和整库导出，作者仓库导入访问 GitHub 公开 API，不要求登录，也不跨浏览器或设备同步。
- GitHub 工作区预置“仓库、工具、文档、其他”分组，复用收藏卡片、搜索、排序、拖拽、回收站和分组管理；只允许 `github.com` 及其子域名，主收藏新增/编辑具体 GitHub URL 时自动归入 GitHub “其他”。
- 精确根路径 `https://github.com/` 是主收藏中的单条共享入口：主页保留普通卡片，GitHub 页在搜索框下固定显示同一条数据；固定入口整卡区域沿用收藏卡片的 hover/focus 上移反馈并可在新标签页打开 GitHub，悬停不额外叠加高亮；右侧提供蓝底白色、与三点菜单同尺寸的纯图标“刷新仓库”按钮，单击会刷新全部已导入作者分组；刷新结束后弹出按作者归纳的详情窗口，列出新增仓库、重复跳过数量及失败原因；入口菜单只保留编辑和删除，无壁纸时使用实体弹层，壁纸下从 1.1.88 起与官方入口共用玻璃材质；入口卡片与分组工具栏之间不绘制全宽分隔线。未收藏时显示同尺寸“添加官方主页”。
- 首次打开工作区会迁移既有具体 GitHub 链接；原“GitHub 收藏已整理”横幅已隐藏，旧版“放回收藏主页”和“一次性撤销整理”均不再提供用户入口；旧 `githubMigration` 数据仍保留兼容读取，官方根入口不参与自动迁移。
- 主收藏和 GitHub 工作区分别保存 `displayModeByWorkspace`；主页继续沿用旧显示方式，GitHub 首次默认为平铺，二者互不影响。popup 打开时按活动标签页 URL 自动选择主收藏或 GitHub 分组，并记住扩展端上次使用的 GitHub 分组偏好，不写入收藏导出。
- 收藏主页、GitHub 页面及任意具体分组的非空搜索都会跨主收藏与 GitHub 工作区统一平铺检索，并显示来源工作区/分组；清空关键词后恢复原工作区和分组，回收站不参与，浏览器历史页保持独立搜索。GitHub 页面提供作者/组织主页导入：公开 REST API 串行分页读取，预览确认后创建或复用带来源记录的作者分组，活动收藏与回收站 URL 全局去重，顶部入口可一次刷新全部来源，刷新只追加且单个来源失败不影响其他成功来源。
- 扩展为作者仓库读取声明最小主机权限 `https://api.github.com/*`；不接入 GitHub 登录或 Token，未登录公开接口可能受每小时 60 次限制。浏览器历史条目链接以新标签页打开，详情页返回后保留历史筛选上下文。版本 1.1.80 生成的固定包为 `artifacts/site-hub-extension.zip`，安装后需在 `chrome://extensions` 或 `edge://extensions` 点击“重新加载”。

## 验收产物归档

- `artifacts/site-hub-extension/` 与 `artifacts/site-hub-extension.zip` 是固定交付路径，不纳入版本子目录。
- 正式截图和录屏按 `artifacts/releases/v<manifest.version>/screenshots|recordings/` 归档；截图脚本与 E2E 从 `public/manifest.json` 读取当前版本并自动创建目录。
- 早期无版本截图保存在 `artifacts/legacy/screenshots/`；Playwright 原始录屏和本地服务器日志分别保存在 `artifacts/working/raw-recordings/` 与 `artifacts/working/logs/`。
- 历史日志不可改写，其中旧的根目录产物路径仅作为当时记录；当前定位规则以 `artifacts/README.md` 为准。

## 安装与重新加载

- 用户从 `chrome://extensions` 或 `edge://extensions` 加载 `dist-extension/` 或 ZIP 解压后直接包含 manifest 的目录；改动后需**到扩展管理页点"重新加载"** 生效（无热更新）。
- 无痕窗口不接管新标签页（平台限制，见 [[Wiki/当前状态|当前状态]]）；扩展无法自行固定到工具栏（平台限制）。

## 平台硬限制

- 扩展无法读取页面 DOM（非内容脚本注入场景）；图标获取依赖 `favicon` 权限与回退链（见 [[Wiki/图标解析体系|图标解析体系]]）。
- Release 构建与 ZIP 上传已由 GitHub Actions 自动完成；版本递增按运行代码改动执行，标签推送按具体发布任务授权执行；不要求固定确认口令。

## GitHub Release 自动发布

- 当前发布仓库为 [`DewMysimple/GuoYoung`](https://github.com/DewMysimple/GuoYoung.git)。
- `.github/workflows/publish-extension.yml` 监听 `v<版本号>` 标签，也支持从 GitHub Actions 手动运行。
- 工作流在 Windows runner 上执行 `npm ci`、`npm run package:extension`，并从 `public/manifest.json` 校验标签版本；成功后创建或更新对应 GitHub Release，上传 `artifacts/site-hub-extension.zip`。
- ZIP 是 Release 的下载资产；`artifacts/site-hub-extension/` 和本地解压目录仍只用于验收或“加载已解压的扩展”，不提交到源码历史。
- 标准发版：递增 manifest 版本 → 完成验证并创建 Git commit → 推送当前分支 → 按发布任务创建并推送同版本标签（例如 `v1.1.20`）→ 在 Release 页面下载 ZIP。安装更新后仍需到扩展管理页点“重新加载”。
