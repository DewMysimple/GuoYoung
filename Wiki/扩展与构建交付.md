# 扩展与构建交付

[[Wiki/MOC_项目知识|← 返回项目知识 MOC]]

## 双模式构建

- 同一套源码，仅以构建模式区分产物（见 [[Wiki/决策/ADR-002|ADR-002]]）：
  - `npm run build` → 网页版 `dist/`。
  - `npm run build:extension`（`vite build --mode extension`）→ MV3 扩展版 `dist-extension/`，接管浏览器新标签页。
- 扩展专属入口与 `manifest.json` 经 `--mode extension` 注入。

## manifest 与权限

- 扩展 manifest 为 MV3；permissions 仅 `favicon` / `activeTab` / `bookmarks` / `search` / `storage`，**不申请全站读取权限**。
- 版本号以 `public/manifest.json` 为单一真源（当前 1.1.20）；网页构建与扩展构建都从该文件复制 manifest，交付前须核对产物版本。

## popup 与书签导入

- 扩展 popup 为**双页签**：当前页操作 + 书签管理（见 [[Wiki/日志/功能添加/第013次|功能添加·第013次]]）。
- 支持**书签导入**为站点，并经存储适配器写入 `chrome.storage.local`。

## 搜索委托

- 新标签页搜索框将查询**委托**给浏览器 search 引擎；原生搜索框不可嵌入（平台限制，见 [[Wiki/当前状态|当前状态]] 遗留项 4）。

## 打包与版本递增

- `npm run package:extension` 经 `scripts/package-extension.ps1` 产出 **ZIP 包**。
- 涉及扩展的改动，**每轮递增 `public/manifest.json` 版本号**并出 ZIP（见 [[Wiki/决策/ADR-011|ADR-011]]）；版本轨迹：1.1.1（冻结槽位/滞回）→ 1.1.2（透明度/层级）→ 1.1.3–1.1.4（跨组落点）→ 1.1.5（分组标签 rAF 交叠反馈）→ 1.1.6（卡片实时交叠落点与分组定向管理）→ 1.1.7（分组弹窗外壳与操作布局统一）→ 1.1.8（非手动排序跨组拖拽）→ 1.1.9（迁移后定向跳转与分组删除双策略）→ 1.1.10（按拖拽发起视图约束迁移后的分组跳转）→ 1.1.11（具体分组的非手动拖拽悬停预览切组）→ 1.1.12（同一次非手动拖拽可预览切回来源分组）→ 1.1.13（分组排序、批量迁移、标签边缘滚动与统一添加入口）→ 1.1.14（分组边界预览与松手提交）→ 1.1.15（纵横分组边界命中后的实时让位推演）→ 1.1.16（链接落点意图单一提交、分组二次删除与长按拖动仲裁）→ 1.1.17（多选标记、分组前后插入与设置外部关闭）→ 1.1.18（分组插入加号移出内容边界并恢复标题对齐）→ 1.1.19（圆形插入加号与连续悬停命中走廊）→ 1.1.20（插入加号自身命中区可直接揭示）。

## 验收产物归档

- `artifacts/site-hub-extension/` 与 `artifacts/site-hub-extension.zip` 是固定交付路径，不纳入版本子目录。
- 正式截图和录屏按 `artifacts/releases/v<manifest.version>/screenshots|recordings/` 归档；截图脚本与 E2E 从 `public/manifest.json` 读取当前版本并自动创建目录。
- 早期无版本截图保存在 `artifacts/legacy/screenshots/`；Playwright 原始录屏和本地服务器日志分别保存在 `artifacts/working/raw-recordings/` 与 `artifacts/working/logs/`。
- 历史日志不可改写，其中旧的根目录产物路径仅作为当时记录；当前定位规则以 `artifacts/README.md` 为准。

## 安装与重新加载

- 用户从 `chrome://extensions` 加载解压的 `dist-extension/` 或安装 ZIP；改动后需**到扩展管理页点"重新加载"** 生效（无热更新）。
- 无痕窗口不接管新标签页（平台限制，见 [[Wiki/当前状态|当前状态]] 遗留项 5）；扩展无法自行固定到工具栏（遗留项 6）。

## 平台硬限制

- 扩展无法读取页面 DOM（非内容脚本注入场景）；图标获取依赖 `favicon` 权限与回退链（见 [[Wiki/图标解析体系|图标解析体系]]）。
- Release 构建与 ZIP 上传已由 GitHub Actions 自动完成；版本递增和标签推送仍需人工确认。

## GitHub Release 自动发布

- `.github/workflows/publish-extension.yml` 监听 `v<版本号>` 标签，也支持从 GitHub Actions 手动运行。
- 工作流在 Windows runner 上执行 `npm ci`、`npm run package:extension`，并从 `public/manifest.json` 校验标签版本；成功后创建或更新对应 GitHub Release，上传 `artifacts/site-hub-extension.zip`。
- ZIP 是 Release 的下载资产；`artifacts/site-hub-extension/` 和本地解压目录仍只用于验收或“加载已解压的扩展”，不提交到源码历史。
- 标准发版：递增 manifest 版本 → 提交并推送 → 创建并推送同版本标签（例如 `v1.1.20`）→ 在 Release 页面下载 ZIP。安装更新后仍需到扩展管理页点“重新加载”。
