# 全工程可维护性体检

[[Wiki/MOC_项目知识|← 返回项目知识 MOC]]

## 结论与范围

维护压力主要来自交互状态过多、异步结果缺少会话边界、数据校验与界面操作规则不一致，以及测试和样式长期集中。既有 components / hooks / lib 分层仍可继续使用；本次按可复现缺陷、引用证据与重复职责进行局部治理，不用文件长度代替质量判断。

本页记录 2026-09-19、1.1.78 的全工程检查：主收藏、GitHub、浏览历史、设置、编辑弹窗、回收站、扩展 popup、书签、后台事件与构建测试入口。使用源码审查、静态引用和依赖图、单元/组件、桌面/触屏浏览器回归及生产截图交叉验证。覆盖矩阵表示检查范围，不表示穷尽所有数据和浏览器条件。

## 冗余与职责收敛

- 删除已无界面调用的 useSiteHub 排序/旧 GitHub 菜单包装方法、未使用导出和书签恒真分支；底层迁移与恢复兼容函数保留。
- 四个编辑器共用 DialogNavigation；设置中的图片异步处理共用 useImageImport，大小与格式校验留在资源处理函数；GitHub 分组顺序归一化共用一个函数。
- CSS 按运行时引用与动态类名人工复核，移除旧历史筛选、旧删除分组弹窗等 38 条规则中的 54 个失效选择器，保留同一规则中仍使用的成员与原有优先级。动态轴、图标尺寸、布局预览类未误删。
- 原 E2E 单文件的 74 个测试体完整迁移到按业务域划分的文件，共用 fixture；增加四个逻辑场景，fixture 统一捕获未处理页面异常。历史断言和桌面/移动项目矩阵保留。
- 静态运行时 import 图未发现循环依赖；该检查不覆盖动态运行行为，不把低引用次数等同于死代码。

## 结构快照与验证结果

本次起点为 1.1.77：App 3,628 行、47 个 useState、37 个 useRef；当前 3,569 行、44 个 useState、30 个 useRef，9 个 useEffect。分组排序改由一个会话接口管理，减少 App 内三份独立 state 与七份 ref。CSS 从 6,002 行降至 5,758 行；行数仅记录范围，不作为性能结论。55 个运行时 TypeScript 文件的静态 import 图未见循环。

最终 30 文件、264 条单元/组件测试通过；E2E 119 通过、37 个既定设备范围跳过、0 失败。网页/扩展生产构建、真实 Chrome 截图和 1.1.78 ZIP 完成；Wiki 校验 0 错误。

## 仍需渐进维护的热点

1. App 中网站拖拽的 DOM/rAF、几何测量和页面编排仍较集中。分组会话已独立，下一步应先提取纯几何与生命周期接口，再考虑展示组件，不能直接搬走一组 setter。
2. 全局 CSS 仍有较多有效样式。清除失效规则后，可随相关需求按组件域整理；加载顺序、优先级和拖拽 transform 是验收约束。
3. 设置和历史大组件仍有自然的局部视图边界，本次优先处理异步和失败路径；不为缩短文件强行拆分。
4. 构建大 chunk 提示继续保留；需要测量依赖及视图占比后决定拆包。依赖审计仍有 Vitest / @vitest/mocker 两项 moderate 开发依赖记录，应以独立升级任务完成兼容性验证。

## 验证边界

- 精确验证结果统一见 [[Wiki/测试与验证基线|测试与验证基线]]；交付记录见 [[Wiki/日志/功能添加/第036次|本次工作日志]]。另补充 v11–v15 缺失偏好读取回归：安全补全显示/排列等字段并保留收藏，读取后满足当前状态类型且幂等。
- 扩展 API 回归使用模拟权限、书签、历史及存储接口；不等于在真实用户配置文件里完成所有权限提示与浏览器原生同步验收。
- popup 写前重新读取能保护操作前已存在的数据，但 chrome.storage.local 仍不是跨页面原子事务；同时写入的冲突需独立设计。
- 取消图片处理会禁止过期结果应用到界面，未增加 IndexedDB 历史图片垃圾回收；未清理历史验收资料或用户资源。
- 本次不改变存储键、state v15、Motion 锁版与拖拽阈值；未引入新的全局状态库。
