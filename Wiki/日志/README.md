# 分类工作日志

本目录是 WebPage 工程记忆的**事件层**，记录每次与 Agent 协作发生了什么。长期有效的事实、决策、架构沉淀为上层主题页（见 `../MOC_项目知识.md`）。

## 分类规则

每轮只有一个主要类型决定物理目录，其他方面写入主题标签：

1. 新功能、行为变化、重构归入 `功能添加`。
2. 纯界面 / 外观 / 样式调整归入 `UI修改`。
3. 已知异常的诊断、恢复、修复归入 `Bug处理`。
4. 解释、比较、架构讨论、计划、待办归入 `工程讨论`。
5. 只做测试、审查、检查、验收归入 `测试验证`。
6. 日志、wiki、文档、配置、依赖、清理、迁移归入 `工程维护`。

混合任务按用户期待的主要交付物分类；实现过程包含测试时仍归实现类（功能添加 / UI修改 / Bug处理）。用户明确指定类型时优先采用用户类型。Agent 在开始实质工作前自动判断，只有本轮尚未封存时才能调整目录。

## 编号与索引

- 六类分别从 `第001次` 起连续编号；不同分类可同时存在同名 `第001次.md`。
- 新编号只取当前分类目录中的最大编号加一，不参考其他分类。
- 日志身份由「对话类型 + 分类序号」共同确定，例如「Bug处理·第001次」。
- 每篇日志必须同时出现在总 MOC 和唯一对应的分类 MOC；总 MOC 按跨分类时间倒序，分类 MOC 按本类编号倒序。
- 历史日志在轮次结束后不改写；需要更正时新增轮次。

## 新日志模板

每次新建日志时复制以下模板，填入对应分类与编号。**日志文件不得以 `---` 开头（不写 frontmatter）**：

```text
# 第NNN次

- 时间：YYYY-MM-DD HH:mm:ss（北京时间）
- 对话类型：功能添加 / UI修改 / Bug处理 / 工程讨论 / 测试验证 / 工程维护
- 主题标签：标签一、标签二
- 源自原轮次：001-002（建设期日志写「无」）
- 本轮目标：……
- 日志索引：[[Wiki/日志/MOC_工作日志|工作日志 MOC]]
- 分类索引：[[Wiki/日志/<分类>/MOC_<分类>|<分类> MOC]]
- 相关知识：[[相关页面|相关页面]]；没有则写「无」

## 已确认的决策

## 检查与操作

## 文件变更

## 测试与验证

## 问题、结果与下一步
```

## 字段填写说明

- **时间**：单点任务写一个时刻，区间任务写 `起—止`。格式 `YYYY-MM-DD HH:mm:ss（北京时间）`。见下方「时间字段口径」。
- **对话类型**：必须与所在目录名完全一致。
- **主题标签**：3-5 个关键词，用顿号分隔；便于 MOC 检索。
- **源自原轮次**：本工程由 45 轮 Codex 对话重构而来；历史日志写覆盖的原轮次区间（如 `011-012`），建设期日志写「无」。这是覆盖率自检字段。
- **本轮目标**：一句话说清这轮要交付什么。
- **日志索引 / 分类索引**：分别链接总 MOC 与所属分类 MOC，两者必须同时出现。
- **相关知识**：链接到上层知识页或 ADR；没有则写「无」。
- **已确认的决策**：列出本轮定下的、后续会遵守的决定；合并单元须写明讨论轮拍板了什么、**被否决的备选方案**。
- **检查与操作**：做了哪些检查、读了什么、执行了什么操作（记目的与范围，不贴大段输出）。
- **文件变更**：按 新增 / 修改 / 删除 分组列路径；只写真实存在的路径，不杜撰。
- **测试与验证**：跑了什么测试、结果如何、关键指标与扩展版本号。
- **问题、结果与下一步**：当前状态、遗留问题、下一轮该做什么；Bug 类必须写**根因**而非只写现象。

## 时间字段口径

- **历史日志（源自原轮次 001-041）**：原始对话导出时 `created` 被统一写成 `2026-08-08 23:20:36`，无法反映真实先后。按 `round_index` 正序从 `22:55:36` 起每分钟 +1 回填至 `23:20:36`，并在时间行内联标注「重建值·源自原轮次 X-Y」。这是**重建值，非真实时刻**。
- **历史日志（源自原轮次 042-045）**：保留真实导出时间，不加重建标注。
- **建设期日志（源自原轮次：无）**：取**执行当日真实墙钟**，严格递增，不回填。**此后新日志一律用真实北京时间，不再回填。**
- 校验：任意两篇日志的 `- 时间：` 时间戳不得完全相同（见 `scripts/wiki-lint.mjs` 规则 23）。
- MOC 时间列只写纯时间戳，保持表格整洁；重建标注仅保留在日志正文时间行。

## 校验命令

    npm run lint:wiki

该命令由 `scripts/wiki-lint.mjs` 提供，校验结构、链接、知识页 frontmatter、日志格式、MOC 排序与源轮次覆盖率。改动 Wiki 后必须跑通再提交。

## 隐私边界

- 只记录决策、命令目的、文件范围、测试摘要、错误类别和最终结果。
- 不复制完整聊天、私人消息正文、内部推理、隐藏上下文、密钥、令牌或大段命令输出。
- 普通问答和一次性输出只留可追溯摘要，不进入长期主题页。
