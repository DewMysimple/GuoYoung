## 已确认的决策

- 历史入口位于顶栏品牌名称右侧，在同一新标签页切换到独立视图；网页构建保留入口并说明仅扩展版可用。
- 通过 Chrome / Edge 兼容的 `chrome.history` API读取当前浏览器配置文件历史，按 URL 汇总、按日期分组，支持全部、今天、昨天、近 7 天和近 30 天筛选。
- `history` 作为可选权限在首次进入历史视图时申请；历史数据不进入 `site-hub:v1`、收藏 state 或导出文件。
- URL 删除、批量删除和范围清理直接调用浏览器历史 API；原生历史变更由 MV3 service worker 通知历史页，并由焦点/可见性恢复时的主动查询兜底。由于公开 API 没有稳定的单次 `visitId` 删除接口，列表和删除粒度均不细化到单次访问。

## 检查与操作

- 回读项目协作契约、项目知识 MOC、当前状态、扩展交付、存储契约和日志模板，确认不新增收藏 state 字段、不更换存储键，并按扩展变更递增版本。
- 核对 Chrome History、Permissions、MV3 service worker 和 Edge API 兼容边界，设计运行时权限、查询、删除、事件通知和网页降级路径。
- 新增浏览器历史适配层与历史视图；顶栏加入入口；扩展构建增加 background service worker；历史列表采用分批渲染，避免大历史量一次性创建全部 DOM。
- 用 redesign-existing-projects skill 审视既有令牌、响应式布局、焦点/悬停/加载/空结果/错误状态，保留现有视觉体系；真实截图检查后移除历史页不适用的收藏页脚文案。
