## 已确认的决策

- 定位为纯前端本地应用：数据只保存在当前浏览器，不引入账号体系。讨论轮明确拍板"无后端"，被否决的备选方案是账号登录 + 云同步 + 多人共享的服务端形态，理由是个人起始页场景不需要为同步付出后端与鉴权成本。
- 技术栈锁定 Vite + React + TypeScript 单页应用，Tailwind CSS v4 承载设计系统，Phosphor 提供统一 UI 图标，Motion 处理进入/弹窗/排序反馈，dnd-kit 承担鼠标、触控与键盘三种拖拽。被否决的方案是套用现成"模板式导航页"，理由是模板无法满足后续自定义与拖拽排序的扩展需求。
- 首版功能边界一次性拉满：编辑、删除、搜索、分类、拖拽排序全部纳入第一版。被否决的备选是先做"只能点开链接"的最小可用版本，理由是没有整理能力的收藏页很快会退化成无法维护的长列表。
- 图标策略确定为三级回退：用户自定义图标地址优先，其次请求站点根目录 favicon，全部失败后显示按名称与域名稳定生成的字母图标。被否决的方案是强依赖第三方图标服务，理由是离线或服务不可用时页面会整体失效。
- 持久化契约定为单一 localStorage 键，首次访问写入示例数据、已有数据不覆盖；分类采用固定预设，第一版不开放自定义分类（保留后续扩展空间）。
- 设计参数锁定为变化度 6 / 动效 4 / 信息密度 5，冷灰中性色搭配单一钴蓝强调色，亮暗双主题，定位是"清爽的桌面工作台"而非花哨门户。

## 检查与操作

- 检查项目目录，确认为空目录，适合从零搭建，不存在需要兼容的历史结构。
- 核对本机前端运行环境，确认使用 npm 管理依赖并兼容当前 Node.js 24。
- 定义三个核心类型：站点条目、分类、以及整体集合状态（含版本号、站点列表、主题偏好）。
- 约定存储键并实现读取校验：结构损坏时保留原值并回退示例数据，同时提供"恢复默认收藏"入口。

```
localStorage key = site-hub:v1
SiteItem: id / name / url / categoryId / customIconUrl? / order / createdAt / updatedAt
SiteCollectionState: version / sites / themePreference
```

- 把状态操作统一封装为添加、更新、删除、排序、重置、主题切换六类动作，禁止组件直接读写存储。
- 实现网址标准化：允许输入域名简写，保存前自动补全协议头、规范化域名并执行重复网址检测。
- 预置约 12 个真实常用站点，覆盖搜索、开发、设计、影音、学习五类，均可被用户修改或删除。
- 实现顶部非对称布局（站点名、全局搜索、主题切换、添加按钮）与下方分类筛选栏 + 响应式收藏网格。
- 卡片交互：点击主体在新标签页安全打开，悬停或键盘聚焦时露出编辑与删除操作。
- 添加/编辑使用可访问的 Radix Dialog；删除前显示确认；表单对网址格式、重复站点、图标加载失败给出明确反馈。
- 搜索同时匹配名称、域名与分类；筛选或搜索状态下禁用拖拽，避免局部排序产生歧义。
- 主题默认跟随系统并可手动切换保存；动效遵循减少动效偏好；移动端降级为单列或双列。
- 先跑类型与构建检查修正编译问题，再补齐单元、组件、端到端三层测试文件。
- 排查测试失败：根因是 Vitest 误把 Playwright 用例当成单元测试加载，属测试范围配置问题而非功能缺陷，已隔离测试范围。
- 处理浏览器运行时缺失：Playwright 的 Chromium 下载在网络阶段长时间无进展，主动中止，改用本机已安装的正式版 Chrome 完成桌面与移动视口验收，覆盖范围不变。
- 视觉巡检发现部分站点 favicon 长时间不返回，导致图标框在加载期间为空，补充了即时字母占位层作为加载中兜底。
