## 已确认的决策

- 修正图标优先级倒置：本地品牌矢量图标不再作为首选，降级为原生 favicon 全部失败后的兜底。讨论轮拍板的完整顺序是自定义地址 → 站点根目录 favicon → DuckDuckGo 镜像 → Google 镜像 → 官方品牌图标 → 名称首字。被否决的方案是继续优先使用本地品牌轮廓（视觉更统一），理由是用户明确要求"用网站原生的图标，不要自己设计"。
- 界面结构回退到"顶部选择栏 + 单一扁平网格"，放弃上一轮的"分组分段展示"。被否决的方案就是保留分段结构，理由是与用户参考图不符；代价是段末添加卡片改为网格末尾常驻添加卡片。
- 桌面网格固定为最多 5 列、卡片约 160px。被否决的备选是让网格铺满容器宽度，理由是 1440px 屏幕会出现约 7 张一行，与参考图的窄网格观感差距明显。
- 引入受保护的"其他"分组作为系统保底：固定排在末尾，不可重命名、不可删除、不可移动；删除普通分组时组内站点统一迁入"其他"，而不是随分组一起消失。被否决的方案是删除分组即删除组内站点。
- 拖拽语义按视图区分："全部"页与搜索状态只浏览、禁用站点拖拽；进入具体分组且无搜索词时才允许组内排序；跨分组移动仍通过编辑站点完成。
- 本轮以电脑端为主要验收目标，保留既有基础响应式能力，但不新增专门的手机端交互设计。这是讨论轮明确缩小的验收范围。

## 检查与操作

- 第一段对话只做只读审查、不改代码：先把交互细节与用户逐条锁定，再进入实现。
- 核对当前实现与参考图的偏差，确认两处：结构上是分段而非选择栏；图标上是本地品牌图标优先。
- 确认兜底必要性——很多个人站点既无可读 favicon 也不在品牌库中，若不定义最终兜底层，卡片会直接显示破图，因此保留名称首字层。
- 先做不改变界面形态的数据基础改造：状态升级到 v3，加入受保护分组标识并扩充分组图标类型。

```
storage key 保持 site-hub:v1
state version: v1 / v2 → v3（读取时自动迁移，不覆盖现有收藏）
SiteGroup 新增：受保护标识 + 扩充的分组图标枚举
分组操作新增：更新图标 / 排序 / 删除并迁移
```

- 实现顶部选择栏：依次展示"全部"、各分组、"其他"与末尾加号，每项显示分组图标与站点数量。
- 加号打开小型"新建分组"弹窗，填写名称并从搜索、代码、设计、影音、学习、工作、工具、文件夹八个预设图标中选择，创建后自动切换到新分组。
- 管理分组弹窗接入重命名、更换图标、拖拽分组排序与删除；"其他"在其中被固定并禁用全部编辑入口。
- 删除普通分组前弹确认，确认后执行站点迁移到"其他"。
- 添加站点的默认分组规则："全部"页取排序第一的普通分组，具体分组页带入当前分组，右上角添加按钮沿用同一规则。
- 搜索作用域限定在当前选择范围内，不跨越当前选中的分组。
- 调整图标解析链路的候选顺序，并让品牌兜底使用官方品牌路径与品牌色；自定义地址失败后继续尝试原生来源。
- 跑生产类型检查，通过后把测试升级到新版交互。
- 新增两类关键验证：旧数据读取时自动补上"其他"分组；原生 favicon 全部失败后才进入官方品牌图标或首字兜底。
- 端到端阶段重点观察两处真实浏览器行为：Radix 双层确认弹窗的可用性，以及网络 favicon 被拦截后能否稳定切换到品牌兜底。
- 视觉捕获中发现一处控制台噪音：某站点根目录 favicon 被对方服务器跨域策略拦截，功能层能自动切到镜像或品牌兜底，但 Chrome 仍记录一次资源错误；已定位具体域名并调整原生图标源的加载方式。

## 问题、结果与下一步

- 结果：图标优先级倒置修复完成，原生 favicon 成为首选来源；顶部分组选择栏与单一网格结构落地；受保护"其他"分组与删除迁移机制建立；状态升级到 v3，v1/v2 数据自动迁移，无收藏丢失。
- 遗留问题一：跨域被拦截的 favicon 仍可能在控制台留下一次资源错误记录，只能通过加载方式规避，无法完全消除外部服务行为。
- 遗留问题二："全部"页禁用拖拽，用户无法对全局展示顺序做手动排序。
- 遗留问题三：手机端交互本轮被排除在验收范围外，存在未覆盖的体验风险。
- 下一步：解决"全部"页也能手动排序的诉求，这需要引入与组内顺序互不干扰的第二套排序字段。
