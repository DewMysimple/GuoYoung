## 已确认的决策

- 图标候选顺序重排为：自定义图标 → Google 高清源（sz=256）→ 站点根目录 favicon → DuckDuckGo 镜像 → 官方品牌矢量 → 名称首字。被否决的是维持"根目录 favicon 优先"，理由是实测很多站点在该位置只返回 16×16 或 32×32，链条一旦被低清图接受，后面更清晰的来源永远不会被尝试。
- 引入 64px 分辨率门槛：自动获取的位图必须不低于 64px 才作为高清结果缓存，低清图继续尝试下一来源；用户填写的自定义图标始终优先且不做尺寸拦截。
- 未知站点若所有来源都不达标，保留候选中尺寸最大的原生图标，而不是直接落到首字。被否决的是"不达标一律用首字"，理由是会丢失站点身份识别度；已知品牌则在全部位图不合格时改用官方品牌矢量。
- 拖拽激活条件从"按压时长"改为"位移距离"：鼠标与触屏统一取消长按等待，位移超过 50px 才进入拖拽。被否决的是保留 150ms/240ms 长按方案，理由是用户明确反馈"非要按上一定时长才能拖太难受"。
- 明确 50px 语义：以按下坐标为原点的二维直线距离，不累计抖动路径；一旦越过阈值，即便随后移回原位，本次手势仍判定为拖拽，松手不打开网站。
- 021 轮新增每站点独立的图标来源选择，只保存该站点自己的选择。被否决的是做成"全局统一切换图标来源"，理由是用户诉求是针对个别站点（高清但不好看）做例外，而非改变整体策略。旧收藏默认走"自动"，旧的自定义图标按"自定义"处理，无需数据迁移。
- 图标来源选择器本轮只在编辑弹窗出现，不进添加弹窗，理由是避免添加流程变得过长。

## 检查与操作

- 检查现有图标回退链与拖拽传感器实现，定位两个直接原因：拖拽仍走 150ms 长按激活；图标链会先接受根目录 favicon。
- 对目标站点做实际尺寸测量，避免只改 URL 参数却拿不到大图。

```
YouTube 根目录 favicon → 16×16
DuckDuckGo 镜像        → 32×32
Google 128 接口        → 128×128
Google 请求 sz=256     → 实际返回 144×144
```

- 据此确认结论：不能只改 CSS 放大，必须同时调整候选顺序并在加载时识别位图真实像素尺寸。
- 确认 50px 规则可直接复用 dnd-kit 现有的"移动距离激活"能力，无需自写计时器；按下仍保留轻微视觉反馈，激活前卡片不位移。
- 核对图标缓存键、加载顺序与卡片按下状态，确保改动不会重新引入切换分组时闪烁或点击误触。
- 把 Google 请求参数改为 sz=256，并在图标加载完成后读取实际位图尺寸做门槛判定。
- 让图标缓存记录最终选中的高清来源，切换分组或卡片重新挂载时直接复用，不闪烁、不叠加首字图层。
- 排查 020 单元测试失败：根因是旧断言仍假设"根目录失败后直接用 DuckDuckGo"，属测试未同步新顺序而非功能错误，其余 52 项已通过；把该缓存用例改为验证新的 Google 高清来源。
- 确认图标尺寸检测不改变数据结构、不清空现有收藏，新的候选 URL 会自然绕开旧的运行时低清缓存。
- 020 真机验证：YouTube 实际加载 Google 高清源，浏览器报告 144×144，页面上首字占位层数量为 0，证明不再叠加。
- 021 检查表单与存储结构，确认新增来源字段可与旧收藏共存，无需迁移。
- 021 在编辑弹窗新增一排紧凑的图标来源预览：自动、高清、网站、镜像、品牌；填写自定义地址后额外出现"自定义"。
- 021 真机检查目标站点：确实呈现 5 个可用来源，其中"网站、镜像、品牌"三项都能给出用户想要的蓝色品牌图标；选择后顶部预览立即变化，保存并刷新后仍保持该来源。
- 处理来源失效兜底：已选来源以后不可用时卡片自动回退到可用来源，不显示破图。

## 问题、结果与下一步

- 结果：高清图标体系建立（sz=256 高清源前置 + 64px 门槛 + 最大尺寸保底 + 品牌矢量兜底），切换分组复用缓存不闪烁；拖拽改为 50px 位移激活，取消长按等待，49px 内松手仍打开网站；每站点可独立指定图标来源，失效自动回退。

- 遗留问题二：图标来源选择器只在编辑弹窗出现，新增站点时无法先看图标再决定。
- 遗留问题三：扩展 ZIP 连续多轮未重新生成。
- 下一步：处理壁纸的连续参数与排列筛选诉求，并把图标来源选择推进到添加流程。
