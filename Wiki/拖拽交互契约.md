# 拖拽交互契约

[[Wiki/MOC_项目知识|← 返回项目知识 MOC]]

> 本工程迭代最频繁、坑最多的区域。任何拖拽相关改动**必须先回读本页**，改动后跑 `npm test` + `npm run test:e2e` 验证。

## 50px 分界

- 以**鼠标/手指直线位移超过 50px** 作为拖拽与点击的唯一判定阈值；49px 及以内一律算点击（见 [[Wiki/决策/ADR-007|ADR-007]]）。
- **不设时间阈值**，避免不同输入设备手感差异导致的误判。

## 误跳转三层拦截

根治"拖拽卡片被当成链接跳转"（见 [[Wiki/日志/Bug处理/第006次|Bug处理·第006次]]）：
1. **页面级手势**捕获 pointer，阻止浏览器默认拖拽/导航。
2. **capture 阶段**拦截，阻止事件冒泡到 `<a>`。
3. 拖拽进行中**临时移除 `href`**，松手后再恢复。

## 冻结槽位与 18px 滞回

- 按下瞬间**冻结几何布局并快照排序**（见 [[Wiki/决策/ADR-008|ADR-008]]）。
- 引入 **18px 滞回**：槽位切换需越过 18px 才生效，抑制边界抖动（见 [[Wiki/日志/Bug处理/第008次|Bug处理·第008次]] 1.1.1）。

## 落点意图与快照提交

- 视觉预览与最终提交**共用同一个落点意图对象**，保证"所见即所得"（见 [[Wiki/决策/ADR-008|ADR-008]]）。
- 跨组拖拽时，切组后**重捕获槽位** + 维护**独立的落点意图**，避免落点与预览不一致（见 [[Wiki/日志/Bug处理/第009次|Bug处理·第009次]] 1.1.3–1.1.4）。
- 1.1.16 起，松手提交只读取当前 `SiteDropIntent`：卡片意图按对应虚线槽插入，分组末尾意图追加到对应组；意图为空即保持拖拽开始快照，不得再使用 `event.over`、悬停标签、分组区域或历史目标二次推断落点。

## 同组 arrayMove 与跨组虚线占位

- 同组排序使用真正的 `arrayMove` **双向语义**，修复"只能向前插"的索引缺陷（见 [[Wiki/日志/Bug处理/第007次|Bug处理·第007次]]）。
- 跨组拖拽显示**虚线占位**表示未来落点，落定后再写数据。

## 450ms 悬停切组与重捕获

- **手动排列**时，拖拽悬停在另一分组上 **450ms** 触发切组，切组后重捕获该组槽位与几何快照。
- 名称/时间排序属于仅迁移模式，标签或分组区域命中后立即成为目标；若从具体分组页发起，目标标签先即时高亮，持续悬停 **450ms** 后在不松手的情况下预览切到目标分组，松手才提交迁移。预览切组可在同一次拖拽中反复改向，原分组始终保持可命中，拖回并悬停 450ms 会预览切回；若从“全部”发起，则只迁移网站并保留当前“全部”显示方式，不触发预览切组。

## 卡片槽位的实时交叠反馈

- 1.1.6 起，同组卡片槽位使用 dnd-kit 提供的实时 `collisionRect`，与拖拽开始时冻结的槽位逐个计算**交叠面积**；最大交叠者成为新候选，无交叠时才回退到卡片中心最近槽位。
- 新候选仍须通过既有 **18px 滞回**，避免卡片停留在槽位边界时来回切换。
- 同组活动卡片的虚线目标框直接使用 dnd-kit 已计算的 transform，因此目标框会在松手前即时移动；不得以 CSS 覆盖该 transform，也不得叠加 framer-motion transform。
- 网站拖拽进行期间，普通卡片的通用 `:hover` / `:focus-within` 高亮必须被中和；只有真实 `is-drop-target`、活动来源和拖拽浮层保留强调反馈，避免无关卡片看起来像落点。
- 跨组仍使用独立虚线占位与落点意图，不改变最终快照提交规则。

## 顶部分组标签的 rAF 反馈

- 拖拽网站时，顶部分组标签仍由 **requestAnimationFrame 逐帧**计算拖拽元素与标签的交叠面积，选择目标分组并提供半透明反馈（见 [[Wiki/日志/UI修改/第005次|UI修改·第005次]]）。
- 该方案来自 [[Wiki/日志/工程讨论/第002次|工程讨论·第002次]] 的录屏逐帧诊断（碰撞自反馈震荡）。

## 非手动排序的跨组迁移

- 1.1.8 起，网站拖拽分成三态：`reorder`（手动排列）、`transfer`（名称/时间排序）与 `disabled`（搜索结果）。
- `transfer` 卡片使用纯 `useDraggable`；来源卡固定原位作为半透明标记，拖拽浮层 1:1 跟随指针，相邻卡片不接收 sortable transform，也不显示卡片插入框或跨组卡片占位。
- 分组排序来源保留蓝色虚线外框；纵向来源内容保持约 0.68 透明度、顶部标签图标与数量保持约 0.52 透明度，以保证拖动时仍可读。窗口 `blur` 或页面 `visibilityState=hidden` 时立即取消网站/分组拖拽，并向 dnd-kit 传感器发送释放事件，禁止浮层和来源拖动状态残留。
- “全部-按分组显示”以目标分组容器作为落点并即时显示整行虚线高亮；特定分组页及“全部-平铺”可直接拖到顶部分组标签。
- 同组释放为无操作。跨组提交只改变分组归属：保留 `globalOrder`，并将站点追加到目标组的手动序末尾；名称/时间视图在提交后按当前规则重新计算位置。
- 从具体分组页发起时，目标标签交叠立即提供反馈，持续 450ms 后内容区预览切到目标分组；拖拽浮层继续跟随指针，松手才提交跨组迁移。预览不会锁定目标：可继续拖到任意其他标签，也可拖回原分组并切回来源内容；最终只按松手时的目标提交。未达到悬停门槛便松手时，迁移成功后仍直接进入目标分组。
- 从“全部”发起时，无论使用平铺还是按分组显示，跨组迁移都不改变当前视图；同组、无目标或取消拖拽同样保持原视图。
- 目标标签和目标区域是唯一目的地反馈；浮层中的分组文字保持来源分组，避免高速跨越多个标签时产生矛盾提示。

## 分组标签长按管理

- 顶部分组标签的 **450ms 长按**只用于打开该分组的管理弹窗，不属于网站拖拽激活逻辑，也不改变网站卡片的 50px 分界。
- 指针移动超过 **8px**、抬起、取消或开始滚动时取消长按；长按成功后抑制紧随其后的合成 click，短按仍只切换分组。
- 同一次按压已经打开定向管理后若继续移动超过 8px，拖动意图优先并立即关闭管理器；分组排序正式开始时再次清除定向管理状态，禁止管理弹窗与拖拽浮层并存。
- 受保护的“其他”允许定向打开查看，但继续禁止改名、换图标、移动和删除。

## 分组排序

- 普通分组可从顶部标签栏横向拖动，也可从“全部－按分组显示”的分组标题纵向拖动；两处都提交到同一份 `SiteGroup.order`。
- 分组排序采用 **8px** 激活距离；顶部标签移动超过 8px 后取消 450ms 长按管理，短按仍只切组。网站卡片继续严格使用 50px 分界，两套阈值不得混用。
- 1.1.15 起，分组排序采用“边界命中、实时让位、松手提交”：独立浮层跟随指针，来源虚线槽与越界范围内的相邻分组由 dnd-kit 排序策略立即移动到预计位置，但 `SiteGroup.order` 只在松手后写入。
- 纵向向上时，指针到达上一组完整区域的底边即预览插到其前；向下时到达下一组顶边即预览插到其后。横向标签使用同样的左右近侧边界规则，不再依赖标题或标签中心点。
- 目标位置只由实时移动过去的来源虚线槽表达，不再叠加独立边界带；视觉让位与最终提交共用 `GroupSortIntent.beforeGroupId`。反向越回原槽、离开排序走廊、Esc 或取消都会清除意图、让布局复原且不写数据。
- 纵向使用 `verticalListSortingStrategy`，横向使用 `horizontalListSortingStrategy`；只能将 `useSortable` 的 transform 应用到分组元素，禁止叠加 framer-motion transform。边界检测读取去除当前 dnd transform 后的几何，避免实时让位反过来改变命中阈值并产生抖动。
- 标签栏边缘自动滚动期间每帧重读可见标签边界并继续更新推演；键盘排序也按相邻边界推进，并通过 live region 宣告预计位置。
- “全部－按分组显示”的分组标题仅挂载鼠标与触屏拖拽监听，不挂载 dnd-kit 键盘 attributes 或 `KeyboardSensor.onKeyDown`；标题图标、名称、数量或空白获得点击焦点后，Space/Enter 必须保持无操作，不得生成浮层、来源虚线槽或修改顺序。顶部标签既有键盘排序不受此限制。
- 分组标题主交互区（图标、名称、数量与排序手柄）声明 `user-select: none` 并使用默认/抓取光标，避免指针经过标题文字时显示文本选择 I-beam；按钮和拖拽手势的既有命中与语义保持不变。
- 受保护的“其他”不可拖动且始终固定末尾。搜索、模态弹窗、多选模式或网站拖拽期间禁用分组排序。
- 分组位移仍只允许 dnd-kit 控制，禁止叠加 framer-motion transform。
- 小组多选与分组拖动的整组外框统一使用紧凑的 18px 圆角；圆角只影响视觉边界，不改变冻结槽位、边界命中、实时让位或松手提交。
- 小组多选与分组拖动的蓝色状态底使用同一块 section surface，并通过与虚线 outline offset 等宽的外扩填充覆盖虚线框内侧；不得再绘制紧凑标题区域的实线内框或 inset 描边。不新增第二个容器或额外命中区域，标题、卡片网格和添加网站卡片保持同一层级。
- “全部－按分组显示”允许选择多个普通分组后拖动其中任一个：选中项按当前相对顺序组成稳定块，非连续选择在目标处收拢；浮层显示代表分组与数量，松手提交块顺序，取消或无有效目标不写数据。拖动未选分组先清除旧选择并退化为单组排序；成功移动后清空分组选择。

## 多选批量迁移

- 多选模式下，拖动已选卡片会把当前选中集合一起迁移；拖动未选卡片会清空旧选择并仅迁移该卡片。浮层以叠放卡片与数量徽标反馈，来源卡保持半透明标记。
- 批量拖拽只负责跨组迁移，不提供同组批量排序；同组、空白处或取消释放均不改数据并保留选择，成功迁移后退出多选并清空选择。
- “全部－按分组显示”可跨多个来源组选取；具体分组页只选择当前组。手动与名称/时间排序都支持批量迁移，搜索状态继续禁用拖拽并退出多选。
- 选择圆圈与勾选状态固定在网站卡片右下角，命中区可向外扩展但不得遮挡左下角分组名称；选中逻辑与批量拖拽语义保持不变。
- 批量迁移保留每个网站的 `globalOrder`，按当前可见稳定顺序追加到目标组手动序末尾；已属于目标组的选中项保持原位。
- “全部－按分组显示”不再使用页面顶部网站多选入口；每个分组标题最右侧都有一份控制同一全局选择态的“多选/切换”按钮，便于长页面就近进入或切换。网站多选与分组多选互斥。
- 标题左侧外置“+”的闲置揭示范围只包含紧凑标题区及加号自身连续命中区；整行空白和最右侧网站多选按钮不会揭示“+”。此规则只约束闲置 UI，链接拖拽时完整分组网格与行内空白仍保持原有命中范围。

## 多选待选择与类型切换

- 在“全部－按分组显示”点击任一分组标题右侧“多选”后，先进入 `pending` 待选择状态：按钮即时改为蓝色“选择”，不显示选择标记；编辑、删除和管理分组入口立即禁用，但卡片打开、标题选择、切换和拖拽交互继续可用。
- 待选择状态下点击紧凑分组标题才进入 `groups`，点击网站卡片才进入 `sites`；进入一种类型后，点击另一种元素不会隐式切换类型。
- `groups` 与 `sites` 都把右侧按钮显示为“切换”；按钮只清空当前集合并进入另一类型的待选择状态，不直接选中元素；如果当前已经是待选择状态，再点击同一按钮立即回到 `none`，不会在两个待选择目标之间循环。点击页面空白、Esc 或取消最后一项会回到 `none`；链接多选取消最后一个链接时保留 `sites` 待选择意图，便于继续点选。小组多选的选中反馈挂在整个 `.grouped-site-section`，使用更明确的浅蓝背景并以蓝色虚线框同时包围标题、卡片网格和添加网站卡片，标题本身不再单独绘制选中框。多选期间卡片编辑、删除与分组管理入口禁用。
- `pending` 时右侧按钮改为“选择”并使用蓝色边框与浅蓝底作为确认提示；进入 `sites` 后分组标题主交互区锁定，仅保留右侧“切换”按钮；进入 `groups` 后普通分组左侧插入位置改为始终可见的圆形勾选框，未选项为白色空圆，选中项为蓝色圆与白色勾，卡片链接不提供打开命中；重复点击标题只取消该组并保留分组多选目标。
- 平铺显示与具体分组页继续只保留顶部网站多选入口；分组选择不扩展到这两种视图。

## 标签栏边缘自动滚动

- 网站拖拽或顶部标签排序期间，指针进入标签栏左右 **56px** 边缘区后以 rAF 自动横向滚动；速度随深入边缘由约 4px/帧递增到 18px/帧。
- 离开边缘、到达边界、松手或取消时立即停止。滚动过程中持续重新计算标签交叠与 450ms 预览切组，允许命中原本不可见的分组并在同一次拖拽中反悔改向。

## 禁用条件

- 下列情况禁止进入拖拽：正在文本输入、搜索结果展示中、模态弹窗打开中、卡片处于禁用态。
- 排序位移只允许 dnd-kit 控制，**禁止叠加 framer-motion 的 transform**（见 [[Wiki/决策/ADR-010|ADR-010]]、[[Wiki/系统架构|系统架构]]）。
