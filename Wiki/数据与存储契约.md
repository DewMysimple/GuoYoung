# 数据与存储契约

[[Wiki/MOC_项目知识|← 返回项目知识 MOC]]

> 所有持久化读写必须经 `src/lib/storage.ts`。任何新增字段或结构变更必须遵循下方铁律。

## 存储键与版本模型

- 存储键**永远为 `site-hub:v1`**，不随版本更换（见 [[Wiki/决策/ADR-003|ADR-003]]）。
- 数据版本号写入 state 内部字段（非键名）。当前版本已演进至 v8。
- 读取时按 `storage.ts` 逐级从 v1 迁移到当前版本。

## 迁移铁律

1. **只补默认字段，绝不覆盖用户已有收藏**。
2. 解析失败时不覆盖损坏的源值，仅回退到安全默认值并记录。
3. 新增 state 字段必须写迁移分支，默认值是安全占位。
4. 迁移幂等：重复迁移不产生副作用。

## clamp 容错与 recovered 语义

- 数值类字段（字号、间距、比例等）读取后做 `clamp` 到合法区间，避免越界导致渲染崩溃。
- 解析异常的数据进入 `recovered` 分支：保留可恢复部分，丢弃损坏部分，不整段丢弃用户收藏。

## SiteItem 双序号

- 每个站点同时持有**组内序号**与**全局序号**两个排序字段（见 [[Wiki/日志/功能添加/第004次|功能添加·第004次]]）。
- 组内视图按组内序号排序；全局/跨组拖拽按全局序号重排，落库时同步回填组内序号。
- 名称/时间排序下的仅迁移拖拽不重排 `globalOrder`；站点移入目标组后追加到该组手动序末尾，再由当前临时排序规则决定显示位置。

## SiteGroup.isProtected

- 分组有 `isProtected` 标志；受保护分组（如"其他"）不被用户删除，仅在加载时对重复"其他"做无损合并。
- 删除普通分组必须显式指定一次性策略：`move-to-other` 将组内网站追加迁入“其他”，`delete-sites` 将网站与分组一并移除；两种结果都重建组序、组内序与剩余全局序，不新增持久化字段。
- 分组排序和指定位置创建继续复用 `SiteGroup.order`：`addGroup(name, icon, beforeGroupId?)` 可插入目标分组之前，写入后统一归一化顺序；受保护的“其他”固定末尾，不新增 state 字段或迁移。

## 批量跨组迁移

- 批量迁移一次性接收选中网站 ID、目标分组与当前稳定可见顺序；已在目标组的网站保持原位，其余选中项按稳定顺序追加到目标组手动序末尾。
- 迁移只更新 `groupId`、受影响组的 `order` 与 `updatedAt`，保留每个网站的 `globalOrder`；同组或没有实际迁移项时返回原快照。

## 导出格式

- 导出/导入为自描述 JSON，包含 state 版本号；导入时按目标版本号走同一迁移路径，保证前向兼容。

## 跨上下文同步

- 网页版用 `localStorage`；扩展版用 `chrome.storage.local`，经存储适配器在运行时切换（见 [[Wiki/扩展与构建交付|扩展与构建交付]]）。
- 扩展多实例（popup / 新标签页）共享 `chrome.storage.local`，写后广播变更以刷新各视图。
