# 数据与存储契约

[[Wiki/MOC_项目知识|← 返回项目知识 MOC]]

> 所有持久化读写必须经 `src/lib/storage.ts`。任何新增字段或结构变更必须遵循下方铁律。

## 存储键与版本模型

- 存储键**永远为 `site-hub:v1`**，不随版本更换（见 [[Wiki/决策/ADR-003|ADR-003]]）。
- 数据版本号写入 state 内部字段（非键名）。当前版本已演进至 v12。
- 读取时按 `storage.ts` 逐级从 v1 迁移到当前版本。

## 迁移铁律

1. **只补默认字段，绝不覆盖用户已有收藏**。
2. 解析失败时不覆盖损坏的源值，仅回退到安全默认值并记录。
3. 新增 state 字段必须写迁移分支，默认值是安全占位。
4. 迁移幂等：重复迁移不产生副作用。

## clamp 容错与 recovered 语义

- 数值类字段（字号、间距、比例等）读取后做 `clamp` 到合法区间，避免越界导致渲染崩溃。
- 解析异常的数据进入 `recovered` 分支：保留可恢复部分，丢弃损坏部分，不整段丢弃用户收藏。

## SiteItem 双序号

- 每个站点同时持有**组内序号**与**全局序号**两个排序字段（见 [[Wiki/日志/功能添加/第004次|功能添加·第004次]]）。
- 组内视图按组内序号排序；全局/跨组拖拽按全局序号重排，落库时同步回填组内序号。
- 名称/时间排序下的仅迁移拖拽不重排 `globalOrder`；站点移入目标组后追加到该组手动序末尾，再由当前临时排序规则决定显示位置。
- 每个站点持有持久化的 `clickCount`；真正打开网站时递增，热量排列按次数降序展示，并列时回到当前手动顺序，不因点击改写 `updatedAt`。

## SiteGroup.isProtected

- 分组有 `isProtected` 标志；受保护分组（如"其他"）不被用户删除，仅在加载时对重复"其他"做无损合并。
- 删除普通分组不再选择处理策略：空组直接删除，非空组把站点以完整快照写入 `deletedSites` 后删除分组；受保护分组仍不可删除。
- 分组排序和指定位置创建继续复用 `SiteGroup.order`：`addGroup(name, icon, beforeGroupId?)` 可插入目标分组之前，写入后统一归一化顺序；受保护的“其他”固定末尾，不新增 state 字段或迁移。

## 批量跨组迁移

- 批量迁移一次性接收选中网站 ID、目标分组与当前稳定可见顺序；已在目标组的网站保持原位，其余选中项按稳定顺序追加到目标组手动序末尾。
- 迁移只更新 `groupId`、受影响组的 `order` 与 `updatedAt`，保留每个网站的 `globalOrder`；同组或没有实际迁移项时返回原快照。

## v9 链接回收站

- v9 新增 `deletedSites: TrashedSite[]` 与 `trashRetentionDays: 7 | 30 | 90 | null`；v8→v9 迁移只补空回收站与默认 30 天，不覆盖已有收藏。
- `TrashedSite` 保存完整 `SiteItem`、删除时间、原分组 ID 和原分组名称。恢复时原分组存在则追加到其手动序末尾；原分组已删除则恢复到受保护的“其他”。
- 应用加载、页面重新可见、期限变更及最近过期时间到达时执行自动清理；`null` 表示永不自动清理。自动过期属于确定性维护，不需要二次确认。
- 网站删除与分组删除都写入回收站；逐项永久删除和清空回收站使用 2 秒内二次点击确认。

## v10 点击热量

- v9→v10 迁移为现有活动站点与回收站快照补 `clickCount: 0`；已有合法计数保持不变，非法或缺失计数归零，不覆盖收藏内容。
- 新增网站与分组资源包导入的网站从 0 次开始；整库导出保留点击计数，分组资源包不携带本机热量数据，导入后重新从 0 次统计。

## v11 GitHub 工作区与 v12 独立显示方式

- `SiteGroup.workspace` 取 `main` 或 `github`；旧版分组在 v10→v11 迁移时补为 `main`，并补齐 GitHub 的“仓库、工具、文档、其他”四个分组。GitHub “其他”受保护且固定在 GitHub 工作区末尾。
- GitHub URL 通过 URL 解析精确匹配 `github.com` 或 `*.github.com`，不匹配 `github.io`、相似域名或无效 URL；精确根路径 `github.com` / `www.github.com` 由 `isGithubHomeUrl` 单独识别为官方共享入口。主收藏中的具体 GitHub 链接自动路由到 GitHub “其他”；GitHub 工作区新增、编辑、拖入和导入拒绝非 GitHub URL，也拒绝直接把官方根入口写入普通 GitHub 分组。
- `https://github.com/` 只有一条 `SiteItem`，归属主收藏并在 GitHub 页顶部渲染共享入口；编辑、删除会同步两个显示位置，旧数据若仍在 GitHub 分组只能经共享入口菜单明确“放回收藏主页”，不会被首次迁移自动改动。
- 首次进入 GitHub 工作区时只移动现有具体 GitHub 站点，不复制数据；`githubMigration` 保存原分组、组内/全局排序、原名称和 URL，支持一次性撤销。撤销只恢复仍在目标组且未被用户移动、删除或修改的站点；原分组不存在时回退主收藏“其他”。迁移横幅不再持久显示，撤销动作位于 GitHub 页更多菜单，并在完成后隐藏。
- 完整导入后统一执行 GitHub 路由；GitHub 站点与 GitHub 分组随整库导出，`githubMigration` 仅为本地撤销记录，不进入导出文件。
- v11→v12 新增 `displayModeByWorkspace: { main: "grouped" | "flat", github: "grouped" | "flat" }`；旧 `displayMode` 只补全 `main`，GitHub 默认 `flat`，已有 v12 工作区选择不会被迁移覆盖。旧 `displayMode` 字段继续保留兼容读取。

## 导出格式

- 导出/导入为自描述 JSON，包含 state 版本号；导入时按目标版本号走同一迁移路径，保证前向兼容。导出明确清空 `deletedSites`，不携带本机回收站；导入与恢复保留本机既有回收站和期限设置。

## 分组资源包

- 分组资源包使用独立的 `site-hub-group-export` 格式和版本号，不会被整库导入流程误识别。
- 资源包只包含来源分组的名称、图标和按组内手动顺序排列的网站便携字段（名称、规范化 URL、可选自定义图标 URL、图标来源）；不包含本机 ID、分组 ID、`globalOrder`、回收站、搜索历史、壁纸或其他设置。
- 从“管理分组”导出当前选中组；导入时追加到当前选中的目标组，保留目标组名称和图标。
- 导入按规范化 URL 做全局去重：现有收藏和资源包内部重复项均跳过，新网站以新 ID 追加到目标组手动序末尾；目标组为受保护的“其他”时仍只追加网站，不修改保护属性。
- 资源包字段验证失败时拒绝整个导入，不静默丢弃无效网站；取消预览确认不写入 state。

## 跨上下文同步

- 网页版用 `localStorage`；扩展版用 `chrome.storage.local`，经存储适配器在运行时切换（见 [[Wiki/扩展与构建交付|扩展与构建交付]]）。
- 扩展多实例（popup / 新标签页）共享 `chrome.storage.local`，写后广播变更以刷新各视图。

## 浏览器历史边界

- 浏览器历史不是 Mysimple state 的字段：历史视图通过 `chrome.history` 查询当前 Chrome / Edge 配置文件，不读取或写入 `site-hub:v1`，也不进入整库或分组资源包导出。
- 历史权限采用 manifest 的可选 `history` 权限，在用户首次进入历史视图时请求；拒绝权限只影响历史视图，不覆盖收藏数据。
- 历史列表按 URL 去重展示；单条、批量和范围清理直接调用浏览器 API，浏览器原生删除则通过历史事件通知与重新查询同步到 Mysimple。
