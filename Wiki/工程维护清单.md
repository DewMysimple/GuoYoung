## 收藏分组公共边界与对齐（1.1.81）

本期解决的是跨职责耦合和生命周期风险。原 App 3,528 行降至 2,181 行，sortable-group-section 289 行降至 36 行；网站事务 682 行、分组排序编排 191 行，几何、原生事件、滚动、误点击和展示各有入口。行数只是范围证据，主要收益是同类交互复用且不再从首次渲染闭包读取旧数据。

- 原列表 20px 缩进、网格 2px padding 和加号固定负偏移叠加导致页面基线不一致。标题操作改为正常行内控件，左右及垂直对齐由浏览器矩形回归约束；长名称/大字号和三种布局都覆盖。
- 原生事件读取最新提交回调；共用窗口取消与边缘滚动，区分 touchcancel 和兼容 pointercancel，并保护取消重入与外部数据更新。
- 平铺/单组/分组统一 CollectionSiteGrid，分组展示、标题、插入菜单、sortable 外壳独立；分组局部 CSS 从全局搬出，移除旧的负偏移/阴影补丁。
- 85 个运行时 TS/TSX 模块的静态相对 import 图未发现循环；无运行时依赖升级。具体修改入口、生命周期及验证边界见 [[Wiki/收藏分组模块边界|收藏分组模块边界]]。

### 复现的边界缺陷

- 选中搜索和设计两组，拖动到纵向排序走廊外松手：顺序未改，但选中框全部消失。定向 E2E 修复前在 is-group-selected 断言失败；根因是 finishGroupSort 无论提交、取消还是无目标，都清空批量选择。清理现在只发生在有效提交后，Esc / 页面空白仍显式退出选择。
- 外部存储更新删除分组后，旧选择集合缺少对应清理；过去只清理已删除网站。hook 回归验证网站、普通分组和锚点随真实数据失效而移除。拖拽预览不是删除依据，悬停切组不丢失来源网站选择。
- 空网站选择开始拖动时，旧逻辑可能同时写入 mode=none 和不可见的单项集合；新状态模型不能表达该组合。此项由状态结构和单元回归约束，未单独宣称浏览器可见 Bug。

### 后续维护顺序与验收门槛

1. **分组排序会话**：把 begin/update/finish/cancel、活动块和意图收进独立 hook；接口使用开始、预览、提交、取消动作。保留 dnd-kit 唯一 transform、8px 激活、其他固定末尾和键盘播报；先覆盖单组/多组、有效落点/无目标/Esc/失焦与刷新持久化，再提取。
2. **网站拖拽会话**：分离纯几何/落点推导与 DOM/rAF 生命周期。保留 50px、18px、冻结槽位、450ms 预览切组和 SiteDropIntent 唯一提交来源；覆盖手动/迁移、平铺/分组、跨组反悔和触屏。
3. **分组展示与测试边界**：在会话接口稳定后提取集合视图；拆 E2E 先共享 fixture，再按收藏、分组、历史、GitHub、设置分域，保留全部断言和项目矩阵。
4. **全局样式与外围编排**：分组/卡片 CSS 整理必须保持规则优先级和桌面/移动截图；GitHub 导入、设置草稿可按各自业务边界继续提取。

每一步均要求职责或状态同步点实际减少；不以压低单文件行数、将同一组 setter 搬到别处、引入第二份全局状态作为完成标准。该段为 1.1.77 快照；拖拽编排已在 1.1.81 按本页顶部边界提取。网页生产 JS 主包约 884.33 kB（gzip 261.77 kB），扩展 main.js 约 628.96 kB，保留大 chunk 提示，未通过调高告警阈值隐藏问题。

- 本机默认镜像不支持 npm audit，返回 404；审计使用单次 `--registry=https://registry.npmjs.org`，未改用户全局 npm 配置。
