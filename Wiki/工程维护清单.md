## 本期结论（2026-09-09）

现有 React 单应用、状态 hook、业务函数与平台适配的分层适合继续迭代；本期以修复工程入口、事实漂移与验证盲点为主，不整体搬迁目录或改写已稳定的交互。以下是本期评估快照，后续状态变化时更新本页。本地 TypeScript 静态运行时 import 检查未发现循环依赖；该检查不代表动态加载与运行时行为的完整证明。

## 可以先保持

| 范围 | 保持的理由 | 何时重新评估 |
| --- | --- | --- |
| src/components、hooks、lib、data 分层 | 已有界面、状态、业务和平台边界，72 个源码 / 测试文件规模无需引入新包架构 | 新功能反复跨层修改、出现循环依赖或多人分工边界冲突时 |
| 单一 useSiteHub 与纯业务函数 | 迁移、回收站、导入已有回归；引入第二份状态源会增加一致性成本 | 明确出现订阅性能或复杂共享状态问题时 |
| dnd-kit + 锁版 Motion | 交互契约成熟，历史回归多；无证据支持本轮重写 | 专项交互需求且有覆盖同一动作的回归与截图时 |
| site-hub 包名、存储键和导出标识 | 是兼容接口，界面品牌统一无需迁移用户数据 | 只有显式设计兼容迁移时 |
| 网页 / 扩展双构建 | 共用源码与业务契约，单一 manifest 版本源清楚 | 增加不同平台入口时 |
| artifacts 分版本目录与固定安装目录 | 已有稳定规范，生成物均忽略；历史证据和正在加载的扩展可能仍有用途 | 用户明确要求清理、先确认保留范围后 |
| 六类日志和 ADR 历史 | 保留决策来源，不能用批量改名或改写抹掉历史 | 通过新日志更正、通过新 ADR 替代 |

## 依赖审计口径

- 本机默认镜像不支持 npm audit，返回 404；审计使用单次 `--registry=https://registry.npmjs.org`，未改用户全局 npm 配置。
- 本期审计生产依赖为 0 项；开发依赖剩余 2 项 moderate，不能据此宣称整个项目无安全问题。
- nanoid 更新是 lockfile 内一个间接开发依赖的补丁；不批量更新生产依赖，不运行 audit fix --force。
- [Vitest 官方安全公告](https://github.com/vitest-dev/vitest/security/advisories/GHSA-82fw-gwwq-j7x9) 指出修复在 4.1.11 / 5.0.0；3.x 无补丁回移。当前仓库配置为 jsdom 单元测试，未启用公告中的独立 mockerPlugin / interceptorPlugin 暴露路径；因此本轮保留审计项、单列升级，不宣称依赖零风险。

## 文件落位与保留规则

- 新组件进入 `src/components/`，状态编排进入 `src/hooks/`，业务 / 适配函数进入 `src/lib/`；测试继续就近。
- README 公开截图放 `docs/images/`，只使用默认或构造数据；验收截图、日志放 artifacts，不提交本地浏览数据。
- 不提交 node_modules、dist、dist-extension、test-results 与临时诊断脚本；本期不删除历史产物。
- 当前状态只写摘要和正在跟踪的事项，逐轮变化写日志，跨会话交互细节写主题页。
